# 결정 기록

- 2026-11-06 · 브라우저 QA 후 중복 입력 · 같은 틱의 제출은 UI의 동기 ref로 한 번만 소비한다. 내용이 같다는 이유로 서로 다른 사용자 턴을 합치지 않는다. 대화 서비스의 기존 직렬화와 재시도 동작은 유지한다.
- 2026-11-06 · 리포트 상태 복구 · 기존 진행 중 작업 맵으로 소유자에게 202 상태를 제공한다. 새로고침 복구는 GET만 사용하고 모델을 자동 재호출하지 않는다. 단일 프로세스 한정이며, 서버 재시작으로 작업이 없어지면 실패 안내 후 명시적으로 재시도한다.
- 2026-11-06 · 교정 근거 · 교정 힌트의 원문 구절은 마지막 사용자 메시지에 있어야 한다. 일치 검사는 공백·대소문자·따옴표 표기만 정규화하고 의미를 새로 추정하지 않는다. 근거 없는 힌트는 제거하고 모델 재호출은 하지 않는다. 리포트의 의미·시제·사실 보존은 생성 지침을 보강하며 실모델 품질은 별도 평가가 필요하다.
- 2026-11-06 · 짧은 리포트의 점수 · 기존 점수 제공은 유지하되 사용자 턴 3개 미만 또는 공백 기준 50단어 미만이면 근거가 제한됨을 화면에 명시한다. 이 기준은 모델의 통계적 신뢰도나 사용자 실력 판정이 아니다.
- 2026-11-06 · 디자인 변경 · 즉시 저장 정책은 유지하고 `router.refresh()`로 폰트·루트 속성을 갱신한다. 설정 폼의 미저장 입력과 테마 미리보기를 보존한다.

- 2026-11-05 · 품질 유지 조건의 비용 최적화 · `chatTurn`의 최상위 `cache_control: {type:"ephemeral"}`로 누적 대화를 캐시하고, 리포트는 사용자·대화 ID와 전체 분석 입력의 SHA-256이 같은 진행 중 요청만 공유한다. 프롬프트·모델·thinking·effort·출력 상한·전사 입력·힌트 정책·리포트 스키마는 변경하지 않는다. 완료·실패한 작업은 즉시 제거해 명시적인 재생성과 재시도를 유지하고, 소유권 검증은 공유 이전에 수행한다. 구조화 출력 축약·원문 요약·effort 하향은 품질 변화 가능성 때문에 적용하지 않는다. 캐시의 출력 동등성 및 사용법: https://platform.claude.com/docs/en/build-with-claude/prompt-caching . 배포는 기존 서버를 유지하고 `NEXT_DIST_DIR`과 포트를 분리한다.
