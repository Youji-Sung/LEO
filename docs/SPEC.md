# LEO 제품 명세

개발자의 해외 취업을 돕는 영어 회화 연습 웹사이트. 사용자는 텍스트 채팅 또는 음성으로 Claude와 영어로 대화하고, 전화 영어가 끝나면 교정 리포트를 받는다.

이 문서는 "무엇을" 만드는지 정의한다. "어떻게"는 `docs/DECISIONS.md`(확정 결정)와 `docs/PLAN.md`(작업 순서)를 따른다.

## 1. 사용자와 운영 전제

- 사용자는 초기 2명. 이메일/비밀번호 로그인. 회원가입 화면은 있되 공개 모집은 하지 않는다.
- 모든 Claude API 비용은 운영자(저장소 소유자)의 단일 API 키에서 나간다. 사용자별 과금은 없다. 사용량은 기록만 한다.
- UI 언어는 한국어, 대화 언어는 영어. 리포트의 설명문은 한국어, 예문과 교정문은 영어.

## 2. 핵심 기능

### 2.1 텍스트 채팅 (언제든지)

- 로그인 후 바로 시작. 테마를 고를 수 있지만 기본값은 "자유 대화".
- Claude는 영어 원어민 대화 상대 역할. 답변은 짧고 자연스럽게(2~4문장), 되묻는 질문으로 대화를 이어간다.
- 응답은 스트리밍으로 표시한다.
- "교정 힌트" 토글: 켜면 사용자의 직전 발화에 대해 한 줄짜리 가벼운 교정을 답변 하단에 작게 표시한다. 꺼져 있으면 대화에만 집중한다.
- 대화는 저장되고, 목록에서 이어서 할 수 있다.
- 채팅 대화도 사용자가 원하면 "리포트 생성" 버튼으로 리포트를 받을 수 있다.

### 2.2 10분 전화 영어

- 테마 선택: `면접(Interview)`, `일상(Daily life)`, `업무 일상(Work day)`, `비즈니스(Business)`. 확장 기능으로 `포트폴리오 면접(Portfolio interview)` 추가.
- 테마별로 Claude의 페르소나와 대화 목표가 다르다 (예: 면접 테마는 면접관, 업무 일상은 동료, 비즈니스는 거래처 담당자).
- 흐름: 테마 선택 → 마이크 권한 확인 → 통화 시작 → 10분 타이머 → 종료(시간 만료 또는 사용자가 끊기) → 리포트 생성 → 리포트 화면.
- 음성 입력은 브라우저 Web Speech API(`SpeechRecognition`)로 텍스트화하고, Claude 응답은 `speechSynthesis`로 읽어 준다. 사용자가 말하는 동안 TTS는 중단한다.
- 통화 중 화면에는 실시간 트랜스크립트, 남은 시간, "끊기" 버튼, 음소거 버튼이 있다.
- Web Speech API를 지원하지 않는 브라우저(예: Safari 일부)에서는 안내 문구와 함께 텍스트 입력으로 대체한다.
- 통화 시간은 설정값으로 바꿀 수 있다(확장 기능 참고). 기본 10분.

### 2.3 리포트

통화(또는 채팅) 종료 후 생성. 구조화된 JSON으로 받아 저장하고 화면에 렌더링한다.

리포트 항목:
1. 요약: 무엇에 대해 이야기했는지 3~5문장 (한국어).
2. 종합 점수: 문법, 어휘, 유창성(응답 길이·주저 표현 기준), 과제 수행(테마 목표 달성) 각 1~10점과 한 줄 코멘트.
3. 문법 교정: 사용자 발화 원문 → 교정문 → 왜 틀렸는지 설명(한국어). 최대 10개, 중요도 순.
4. 어휘 제안: 사용자가 쓴 단순한 표현 → 더 자연스러운 표현, 의미, 예문. 최대 10개.
5. 더 나은 표현: 사용자 발화 중 3개를 골라 "원어민이라면 이렇게" 재작성.
6. 다음 연습 과제 3개: 구체적인 행동 지침.
7. 테마가 면접류이면: 답변 구조(STAR 등) 피드백과 예상 추가 질문 3개.

리포트는 목록에서 다시 볼 수 있고, 대화 트랜스크립트도 함께 열람할 수 있다.

### 2.4 사용량 기록

- Claude API 호출마다 사용자, 기능(chat/call/report/portfolio), 모델, 입력·출력·캐시 토큰, 추정 비용(USD), 소요 시간을 기록한다.
- "사용량" 페이지에서 사용자별·기간별 합계와 최근 호출 목록을 본다.
- 추정 비용 단가는 설정 파일에 두어 바꿀 수 있게 한다.

## 3. 확장 기능 (핵심 기능 완료 후 진행)

### 3.1 포트폴리오 기반 면접 준비

- 사용자가 포트폴리오를 등록한다: 텍스트/마크다운 붙여넣기, 또는 PDF 업로드(텍스트 추출).
- 등록된 포트폴리오를 바탕으로 "포트폴리오 면접" 테마에서 Claude가 실제 프로젝트 내용을 파고드는 면접 질문을 한다.
- 리포트에 "기술 설명의 명확성" 평가 항목이 추가된다.
- 포트폴리오는 여러 개 등록 가능, 통화 시작 시 선택.

### 3.2 연장 통화

- 통화 길이를 10/20/30분 중 선택할 수 있다. 기본 10분.
- 통화 중 남은 시간이 1분일 때 "10분 연장" 버튼이 나타난다(최대 30분).
- 긴 통화는 트랜스크립트가 길어지므로 리포트 생성 시 입력 길이를 고려한다(요약 후 분석 또는 전체 입력, 세션이 판단).

## 4. 비기능 요구사항

- 반응형: 데스크톱과 모바일 브라우저 모두에서 통화 화면이 쓸 만해야 한다.
- 접근성: 키보드로 주요 흐름 조작 가능, 버튼에 레이블.
- 테스트: 단위 테스트(서비스 계층), 통합 테스트(API 라우트), E2E(핵심 흐름 3개: 로그인→채팅, 로그인→통화→리포트, 포트폴리오 등록→면접). E2E는 `CLAUDE_MOCK=1`로 돌린다.
- 비밀값은 절대 커밋하지 않는다. `.env.example`만 커밋.
- 운영 비용 보호: 한 통화에서 Claude 호출 횟수와 토큰이 폭주하지 않도록 서버에서 대화 길이 상한을 둔다(예: 통화 1회당 최대 60턴).

## 5. Claude API 사용 규칙

세션은 API 코드를 작성하기 전에 `/claude-api` 스킬을 먼저 로드하고 TypeScript README를 읽는다. 아래는 그 스킬과 일치하는 요약이며, 충돌 시 스킬이 우선한다.

- SDK: `@anthropic-ai/sdk`. 직접 fetch로 호출하지 않는다.
- 키: `process.env.LEO_ANTHROPIC_API_KEY`를 `new Anthropic({ apiKey })`에 명시적으로 넘긴다. `ANTHROPIC_API_KEY`라는 이름은 쓰지 않는다.
- 모델: 기본 `claude-opus-5`. `LEO_CLAUDE_MODEL`로 바꿀 수 있게 한다. 모델 ID에 날짜 접미사를 붙이지 않는다.
- thinking: `thinking: { type: "adaptive" }` 또는 생략. `budget_tokens`는 쓰지 않는다.
- effort: 대화 턴은 `output_config.effort = "low"`(짧고 빠른 답변), 리포트는 `"high"`.
- 스트리밍: 대화 응답은 `client.messages.stream()`으로 받아 클라이언트에 그대로 스트리밍한다.
- 구조화 출력: 리포트는 `output_config.format`(JSON 스키마)으로 받는다. assistant 프리필은 쓰지 않는다(400 오류).
- 프롬프트 캐싱: 테마별 시스템 프롬프트는 고정 문자열로 두고 `cache_control`을 건다. 타임스탬프 등 가변 값은 시스템 프롬프트에 넣지 않는다.
- `stop_reason`이 `refusal`이면 사용자에게 안내 문구를 보여 주고 대화를 계속할 수 있게 한다. `fallbacks: "default"`와 해당 베타 헤더를 기본으로 켠다.
- 사용량: 모든 응답의 `usage`를 사용량 테이블에 기록한다.
- 모킹: `CLAUDE_MOCK=1`이면 SDK를 호출하지 않는 모의 구현을 쓴다. 모의 구현은 스트리밍과 리포트 JSON 스키마를 그대로 흉내 낸다. 테스트는 항상 모의 구현으로 돈다.

## 6. 화면 목록

1. 로그인 / 회원가입
2. 홈(대시보드): 최근 통화·채팅, 바로 시작 버튼
3. 채팅
4. 통화 설정(테마·시간·포트폴리오 선택) → 통화 화면 → 리포트 화면
5. 기록(통화·채팅 목록, 리포트 열람)
6. 포트폴리오 관리
7. 사용량
8. 설정(교정 힌트 기본값, TTS 음성 선택, 통화 기본 길이)
