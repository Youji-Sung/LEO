# UX 라이팅 가이드 (2단계)

한국어 UI 문구 규칙과 용어집. 근거는 `RESEARCH.md` 2부(F-1 국립국어원, F-2 토스, F-3 해요체, F-4 버튼, C 마이크로소프트, D Polaris, E Atlassian, A NN/g, G Duolingo)와 `PRINCIPLES.md` 의 톤 결정이다. 모든 문구는 `src/content/ko.ts` 한 곳에 있고 컴포넌트·서비스는 거기서 가져온다. 개정표는 이 문서의 4절.

## 1. 목소리

차분한 코치(PRINCIPLES 2절). 짧고 구체적이며 평가하지 않는다. 사용자에게 할 일을 말하고, 시스템이 한 일을 말한다. 과장·유머·이모지·밈 없음.

## 2. 규칙

### 2.1 경어: 해요체 전면

- 평서 "~해요/~돼요", 의문 "~할까요?", 지시 "~하세요", 부탁(사용자에게 불편을 끼칠 때) "~해 주세요". 오류·안내·버튼 설명 모두 같다.
- "~하시겠습니까?", "~하십시오", "~께서", "~되어집니다" 를 쓰지 않는다. "되어요" 는 "돼요" 로.
- 근거: 토스 "제품 안의 모든 문구는 해요체"(F-2c), 해요체는 문장 유형이 바뀌어도 어미가 "~요" 로 일정해 목소리가 흔들리지 않음(F-3 출처 1), 격식체 자체는 만족감에 주효과가 없고 쉬운 말이 핵심(F-3 출처 5). 국립국어원도 고압적 명령형 대신 "~하세요" 를 예시(F-1 21쪽).
- 예외 없음. 되돌릴 수 없음·정책 제한 같은 사실 고지도 "삭제하면 되돌릴 수 없어요" 처럼 해요체 평서로 쓴다(DECISIONS 1단계).

### 2.2 버튼

- 화면의 주 행동(1차 버튼, 화면당 하나)은 **목적어 + "~하기"** 로 끝난다: "통화 시작하기", "채팅 시작하기", "리포트 만들기", "포트폴리오 추가하기", "가입하기". 목적어가 자명하면 줄인다("보내기", "저장하기").
- 보조 버튼·전환 버튼은 **명사형 2~5자**: "다음", "닫기", "취소", "삭제", "다시 시도", "미리 듣기", "리포트 보기", "로그아웃".
- 파괴적 확인 대화의 버튼은 행동 이름 그대로: [삭제] [취소]. "확인/OK" 를 쓰지 않는다. 일반 안내 대화의 닫기 버튼은 "닫기".
- 한 화면에서 두 버튼이 같은 결과로 가지 않는다. 버튼 라벨은 누르면 무슨 일이 생기는지 예측하게 한다("다음" 은 뒤에 무엇이 오는지 본문이 말해 줄 때만).
- 로그인·로그아웃·회원가입은 관용어라 그대로 쓴다.
- 근거: 토스 단독 CTA "~하기"(F-2b), Polaris `{verb}+{noun}`(D-5), Atlassian "OK 금지·명령형 동사 1~2어절"(E-3, E-5), 토스 "닫기"(F-2c), ppss "취소의 중의성·두 버튼 같은 결과 금지"(F-4 출처 4).

### 2.3 길이와 구조

- 한 문장에 정보 하나. 본문은 2문장 이내, 제목은 3~4어절, 통화 중 상태는 1줄(모바일 2줄까지).
- 핵심을 앞에: 무슨 일이 → 그래서 할 일.
- 잡초 뽑기: "앞으로", "정말", "꼭", "한번", "바로", "지금" 처럼 빼도 뜻이 같은 단어는 뺀다.
- "~하실 수 있어요" 보다 동사 지시("~하세요"). "~하는 것이 가능합니다" 금지.
- 근거: 국립국어원 "문장은 간결하고 명료하게"(F-1), 토스 Weed cutting·Focus on key message(F-2), Microsoft "bigger ideas, fewer words"(C-3), Atlassian 제목 3~4어절·본문 1~2문장(E-3), KRDS 1줄(F-1b).

### 2.4 구두점

- 제목·버튼·레이블·옵션·칩·플레이스홀더·탭: 마침표 없음.
- 본문·오류·안내·빈 상태·상태 메시지(문장형): 마침표 있음. 두 문장이면 둘 다.
- 느낌표: 쓰지 않는다. 리포트 요약 첫 문장에서도 쓰지 않는다(축하는 내용으로).
- 물음표: 사용자가 결정하는 진짜 질문에만("삭제할까요?").
- 말줄임표 "…" 는 진행 중 상태에만 쓰고, 상태 문구는 "~하는 중" 으로 끝낸다. "…" 단독 표시 금지.
- 가운뎃점(·)은 메타 정보 구분에만, 한 줄에 3개까지.
- 근거: Microsoft #7(C-3), Polaris 구두점(D-4), Atlassian 느낌표 금지(E-7), Google 느낌표 회피(B-3).

### 2.5 영어 혼용

- 대화 내용(상대 말, 내 말, 예문, 교정문, 예상 질문)은 영어 그대로. 한국어 문장 안에 영어 문장을 인용할 때는 따옴표 없이 별도 줄·블록으로 보여 준다.
- 테마 이름은 한국어("면접", "일상", "업무", "비즈니스", "자유 대화", "포트폴리오 면접"). 영어 병기 안 함.
- 고유명사·파일 형식·키 이름은 영어 그대로: Claude, Chrome, PDF, Enter, Shift. 운영자 전용 문구에만 `LEO_ANTHROPIC_API_KEY` 같은 변수명을 쓴다.
- 약어 금지: TTS → "상대 목소리", STT → "음성 인식", API → 사용자 문구에서 "Claude 연결"(운영자 문구에서만 "API 키"). AI 단독 사용 금지 → "상대".
- 외래어는 외래어 표기법대로: 리포트, 포트폴리오, 테마, 마이크, 메시지, 토큰.
- 근거: 국립국어원 외래어·약어 남용 금지, 로마자 단독 노출 주의(F-1), 토스 Zero Jargon(F-2b).

### 2.6 숫자·시간

- 아라비아 숫자, 단위 붙여쓰기: "10분", "20초", "60번", "3개", "188자".
- 타이머: "m:ss"(9:58). 1분 이하 경고 문구는 "1분 남았어요".
- 날짜·시각: 오늘은 "오늘 14:05", 어제는 "어제 09:12", 올해는 "11월 3일 09:12", 그 밖에는 "2025년 3월 2일 09:12". 구현은 `formatDateTime` 한 곳.
- 토큰: 천 단위 쉼표 "12,340". 비용: 소수 둘째 자리 "$0.11", 1센트 미만은 "$0.01 미만", 0은 "$0.00".
- 점수: "6/10" 표기와 함께 해석 라벨(SYSTEM 에서 정의: 8~10 좋아요, 5~7 괜찮아요, 1~4 연습이 필요해요).
- 근거: Material 아라비아 숫자(B-2), Polaris 네 자리 이상 쉼표(D-4), Vercel 숫자 tabular(3부).

### 2.7 오류 메시지

구조: **무슨 일이 생겼는지**(상태 서술, 주어 없이) + **할 수 있는 것**(동사 지시 또는 버튼). 원인은 알 때만 짧게.

- 비난하지 않는다: "권한을 거부하셨어요" → "마이크 권한이 꺼져 있어요".
- "죄송", "부탁", "실패!", "에러", "오류가 발생했습니다" 를 쓰지 않는다. 사과는 데이터 손실에만.
- 기술 용어·코드·상태 번호 금지: "스키마 검증 실패", "502", "JSON" 금지. 내부 원인은 로그에만.
- 원인별로 다른 문장: 권한 없음 / 마이크 없음 / 네트워크 / Claude 연결 안 됨 / 한도 / 운영 설정 없음.
- 입력을 보존하고 재시도 버튼을 준다. 토스트형은 한 구절("연결이 끊겼어요").
- 운영자만 고칠 수 있는 문제는 "운영자에게 알려 주세요" 로 끝내고, 변수명 같은 세부는 운영자용 문구(배너·설정)에만 둔다.
- 근거: NN/g 오류 가이드(A-2), Microsoft 문제→원인→해결·please/sorry 금지(C-4, C-5), Atlassian(E-3), Polaris(D-3), 토스 "다음 화면으로 넘어가게 하는 안내"(F-2d).

### 2.8 빈 상태

구조: **상황 한 문장**("아직 통화 기록이 없어요.") + **다음 행동 버튼 1개**("통화 시작하기"). 오류와 빈 상태를 섞지 않는다. 할 일이 없는 빈 상태(교정할 문장 없음)는 완료로 쓴다("이번 대화에는 다듬을 문장이 없었어요.").
근거: NN/g 빈 상태(A-3), Polaris·Atlassian 빈 상태(D-5, E-6).

### 2.9 로딩·진행

- "대상 + ~하는 중": "리포트를 만드는 중", "답변을 기다리는 중", "마이크를 확인하는 중".
- 10초를 넘기는 작업(리포트)은 예상 시간을 붙인다: "보통 1분 안에 끝나요."
- 1초 안에 눌림 피드백, 2~10초 스피너+문구, 10초 이상 단계·시간 안내.
- 근거: NN/g 진행 표시(A-4), 스켈레톤(A-6).

### 2.10 확인 대화(파괴적 행동)

제목은 질문 "포트폴리오를 삭제할까요?", 본문은 결과와 되돌릴 수 없음 "삭제하면 되돌릴 수 없어요.", 버튼 [삭제] [취소]. 브라우저 `confirm` 을 쓰지 않는다(SYSTEM 의 Dialog).
근거: Atlassian 위험 행동 확인(E-5), Polaris 예측 가능한 버튼(D-5).

### 2.11 칭찬과 교정의 균형(리포트)

- 요약 첫 문장은 한 일·성취를 사실로 인정한다("10분 동안 면접 질문 6개에 답했어요."). 그다음 문장부터 다듬을 점.
- 교정은 원문 → 고친 문장 → 이유 한 줄. 판정어("틀렸어요", "오류", "실수", "잘못") 대신 "이렇게 말해요", "~로 써요".
- 칭찬은 구체적 사실 하나, 매번 반복하지 않음. "완벽", "최고", "성공적으로" 금지.
- 점수 코멘트는 한 줄, 다음 행동으로 끝나면 좋다.
- 이 규칙은 Claude 가 만드는 문장에도 적용되므로 `prompts/themes.ts` 의 리포트 문체 지시에 반영한다(모의 응답으로만 확인).
- 근거: Duolingo recast·노력 인정(G-1, G-2), 토스 "고생 인정 한 줄이 지표를 올림"(F-2b), Atlassian 성공 메시지 "꽃다발이지 강아지가 아니다"(E-4), 과장 포장 금지(F-2e).

### 2.12 금지 표현 목록

| 금지 | 대신 |
|---|---|
| ~하시겠습니까, ~하십시오, ~바랍니다 | ~할까요?, ~하세요 |
| 확인(버튼) | 행동 이름(삭제·저장·닫기) |
| 성공적으로, 완료!, 축하합니다! | 결과를 문장으로("저장했어요.") |
| 죄송합니다, 부탁드립니다 | (쓰지 않음) |
| 오류가 발생했습니다, 실패했습니다, 에러 | 무슨 일이 생겼는지 서술("답변을 받지 못했어요.") |
| 잘못된, 유효하지 않은, 올바르지 않은 | 무엇이 맞는지("8자 이상이어야 해요") |
| ~되어집니다, ~에 의해, ~함에 있어, ~에 대한 | 능동형·우리말 어순 |
| 생성, 등록, 취득, 제고 | 만들기, 추가, 받기, 높이기 |
| TTS, STT, API(사용자 문구), AI | 상대 목소리, 음성 인식, Claude 연결, 상대 |
| 스키마, JSON, 502, 토큰(사용량 화면 제외) | (사용자 문구에 쓰지 않음) |
| 이모지, 밈, 유행어, "간단히", "쉽게" | (쓰지 않음) |
| 님 남발("개발자 1님, 안녕하세요!") | 이름은 홈 인사 한 곳에서만 |

## 3. 용어집

같은 개념에 한 단어. 선택과 이유.

| 개념 | 쓰는 말 | 쓰지 않는 말 | 이유 |
|---|---|---|---|
| 음성 대화 기능(메뉴·기능명) | 전화 영어 | 콜, 보이스 | 제품 설명·README 와 일치, 사용자가 아는 말 |
| 한 번의 음성 대화(행위·기록 단위) | 통화 | 세션, 콜 | "통화 시작", "통화 중", "통화 기록" 으로 자연스럽게 활용됨 |
| 텍스트 대화 기능 | 채팅 | 메시지 대화, 텍스트 모드 | 현행 유지, 짧음 |
| 채팅·통화를 아우르는 기록 단위 | 대화 | 세션, 히스토리 | 기록 화면·통계에서 둘을 함께 부를 말 |
| 대화 상대(AI 페르소나) | 상대 | AI, 파트너, 튜터, 면접관, 봇 | 테마마다 역할이 다르고 UI 는 역할을 판정하지 않는다. "AI" 단독은 약어 금지 규칙 |
| 사용자 자신 | 나 | 당신, 회원 | 말풍선 화자 라벨 "나"/"상대" |
| 사후 피드백 문서 | 리포트 | 보고서, 피드백, 결과 | 익숙한 외래어, 짧음. 처음 소개할 때만 "교정 리포트" |
| 문법 고침 | 교정 | 수정, 고치기, 첨삭 | 리포트 섹션명·힌트명과 일치 |
| 어휘·표현 제안 | 제안 | 추천, 대체 | 교정(틀림)과 제안(더 나음)을 구분(Grammarly 의 정확성/개선 분리) |
| 대화 중 한 줄 교정 | 교정 힌트 | 힌트, 팁 | 현행 유지 |
| 대화 상황 종류 | 테마 | 주제, 시나리오, 모드 | 익숙함, 짧음 |
| 대화 내용 전체 열람 | 대화 내용 | 트랜스크립트, 전사, 스크립트 | 국립국어원 외래어 남용 금지. 통화 중 실시간 영역은 "대화" |
| 상대 음성 출력 설정 | 상대 목소리 | TTS 음성, 음성 합성 | 약어 금지, 사용자 관점 |
| 내 말을 글로 바꾸는 것 | 음성 인식 | STT, 받아쓰기 | 브라우저 지원 안내에서만 등장 |
| 마이크 권한 점검 | 마이크 확인 | 권한 테스트 | 짧고 결과("확인했어요")와 호응 |
| 통화 종료 버튼 | 끊기 | 종료, 나가기 | 전화 관습(iOS/Android "End call") |
| 시간 추가 | 10분 연장 | 더 하기 | 현행 유지, 숫자 명시 |
| 이력서 자료 | 포트폴리오 | 이력서, 자료 | 제품 기능명 |
| 포트폴리오 넣기 | 추가 | 등록, 업로드(파일 올리기에만) | "등록" 은 행정 한자어 |

## 4. 개정표

`STRINGS.md` 의 사용자 노출 347행 전부에 대한 "원문 → 개정 → 이유" 는 `STRINGS-REVISED.md` 에 있다(0단계 행 번호 기준, 유지한 행도 "유지, 이유"). 개정 문구의 단일 출처는 `src/content/ko.ts` 이며, 표와 코드의 일치는 PROGRESS 2단계에 grep 결과로 적었다.

주요 개정 결정(요약)
- 전면 해요체. "~습니다/~하세요" 혼재를 "~해요/~하세요" 로 통일.
- 주 버튼 "~하기": 새 채팅 시작 → 채팅 시작하기, 통화 시작 → 통화 시작하기, 리포트 생성 → 리포트 만들기, 등록 → 포트폴리오 추가하기, 다음 → 다음(본문이 "마이크를 확인한 뒤 통화 화면으로 가요" 로 예고).
- 트랜스크립트 → 대화 내용, 등록 → 추가, 생성 → 만들기, TTS 음성 → 상대 목소리, 턴 상한 → 대화 횟수 한도.
- 오류 전부를 "무슨 일 + 할 일" 구조로, 기술 정보 제거(리포트 스키마 오류·HTTP 상태).
- 빈 상태 전부에 다음 행동 문장 추가(버튼은 화면 컴포넌트에서).
- 운영자 배너를 사용자 문구에서 분리하고 변수명은 운영자 문구에만.
- 날짜 상대 표기(오늘/어제), 비용 2자리.
