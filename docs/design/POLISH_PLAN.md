# 디자인 시안 4종 다듬기 계획

전제와 범위는 `VISUAL_BRIEF.md`의 "다음 작업" 절. 기본·서재·무대·콘솔은 모두 사용자가 설정에서 고르는 정식 기능이며, 하나를 없애거나 기본값을 바꾸지 않는다. 각 단계 안에서 무엇을 어떻게 고칠지는 세션이 정하고 `DECISIONS.md`에 "결정 · 근거 · 기각한 대안"으로 적는다.

공통 규칙
- **항목 하나를 끝낼 때마다 `npm run check`를 통과시키고 커밋·push한다.** 세션이 중간에 끊겨도 끝난 작업이 남게 하기 위해서다. 단계 끝에는 `npm run test:e2e`도 통과시킨다.
- 네 시안을 모두 확인한다. "기본에서만 확인"은 확인이 아니다. 스크린샷은 `scripts/screenshots.ts --direction <시안>`으로 찍는다.
- 진행 기록은 `docs/design/POLISH_PROGRESS.md`에 "- [x|미확인] 조건 — 확인 방법 — 결과(수치)" 형식으로.
- 실제 Claude API는 호출하지 않는다(`CLAUDE_MOCK=1`).

## 1. 외부 테스트 피드백 반영

`VISUAL_BRIEF.md` "외부 테스트 피드백" 6건. 각 건마다 어떻게 고칠지(또는 고치지 않을지) 세션이 정하고 근거를 적는다. 고치면 네 시안에서 모두 확인한다.

1. 통화 상대의 첫 인사말이 대화 내용·메시지 수에 빠짐 (Claude API는 첫 메시지가 user여야 하는 제약이 있다. 저장한다면 API로 보낼 히스토리에서는 빼는 처리가 필요하다)
2. 빈 채팅의 예시 문구가 예시인지 구분되지 않음
3. 메시지 없는 대화가 기록 목록에 "주고받은 말 없음 / 진행 중"으로 남음
4. 마이크 없는 브라우저에서 "마이크 권한이 꺼져 있어요"가 오류색으로 뜨고 그 아래 "글로 대화해요" 안내가 겹침
5. 통화에서 실패한 말이 사라지고 다시 보내기가 없음(채팅에는 있음)
6. 리포트 문법 교정이 가끔 사소하거나 중복됨(프롬프트에 규칙은 있음. 더 할 수 있는 것이 있으면)

완료 조건: 6건 각각 "조치 또는 미조치와 이유"가 PROGRESS에 있고, 조치한 것은 테스트(단위·통합·E2E 중 맞는 것)가 있다.

## 2. 미촬영 화면을 네 시안으로 촬영하고 깨진 곳 수정

1차 시안 세션은 9개 상태만 찍었다. 나머지 화면(채팅 목록, 대화 내용, 포트폴리오 빈/목록/삭제 다이얼로그, 사용량, 설정, 회원가입, 로그인 오류, 토스트, 리포트 오류·재시도, 통화 종료 중, API 키 없음 배너 등 `screenshots/after/index.md`의 42개 상태 전부)을 **네 시안 × 1280/390 × 라이트/다크**로 찍는다.

깨진 곳(겹침, 넘침, 안 보이는 글자, 시안 토큰이 안 먹은 요소, 대비 미달)을 고친다.

완료 조건: 시안당 42개 상태 × 4변형 스크린샷이 `screenshots/directions/<시안>/`에 있다. axe 위반 0, 가로 스크롤 0을 전 장에서 자동 확인한 결과가 PROGRESS에 있다.

## 3. 시안별 "CSS만으로 못 한 것" 해결

각 시안 README 10절의 목록(서재 7, 무대 7, 콘솔 10). 마크업이 필요하면 공통 마크업을 바꾸되 네 시안이 모두 깨지지 않게 한다. 세 시안 공통인 `theme-color`도 시안 캔버스색으로.

완료 조건: 24건 각각 "해결 / 다른 방법으로 해결 / 안 함(이유)"이 PROGRESS에 있다. 바뀐 화면은 2단계와 같은 방식으로 재촬영.

## 4. 검증

- 대비: 시안별 토큰 조합도 `tests/unit/contrast.test.ts`에 고정(현재는 기본만). 네 시안 × 라이트/다크 전부 텍스트 4.5:1, UI 3:1.
- 반응형: 360/640/768 폭을 네 시안으로. 가로 스크롤 0.
- reduced-motion: 시안별 모션(무대의 펄스, 콘솔의 깜빡임 등)에 대체 동작이 있는지 촬영으로 확인.
- 키보드 E2E 3개가 시안과 무관하게 통과(시안 쿠키를 넣은 변형 1회씩).
- 성능: 시안별 첫 로드 폰트·CSS 전송량과 CLS(`scripts/perf.ts`).

완료 조건: 위 항목마다 수치가 PROGRESS에 있다.

## 5. 리뷰 패스

서브에이전트 2개에게 자료만 주고 결론을 주지 않는다. (a) 네 시안의 스크린샷 전체 + 각 시안 README 1~3절: "그 시안이 스스로 말한 의도에서 벗어난 곳, 시안 간 일관성 문제". (b) 코드: "정확성 버그·접근성 결함". 확인된 것만 고치고 미조치는 이유와 함께.

## 6. 마무리

- `docs/design/directions/README.md`를 "사용자 기능" 기준으로 갱신(비교표, 각 시안의 상태, 남은 과제).
- 프로젝트 README의 설정 기능 설명 갱신.

- 마지막 메시지: 바뀐 것, 피드백 6건 처리 결과, 검증 수치, 미확인 항목, 운영자가 실제 기기에서 볼 것.
