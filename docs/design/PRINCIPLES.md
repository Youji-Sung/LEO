# 톤과 디자인 원칙 (1단계)

근거 자료: `RESEARCH.md`(가이드라인·레퍼런스 발췌), `AUDIT.md`(현황 문제 81건), `BRIEF.md`(사용자·상황 출발점). 결정의 기록은 `DECISIONS.md` 1단계 절에도 있다.

## 1. 사용자·상황 분석

출발점(BRIEF): 해외 취업을 준비하는 한국인 개발자, 영어 회화에 자신이 없고 면접이라는 시험을 앞두고 있다. 사용자 2명. 데스크톱 Chrome 위주, 통화는 모바일 가능성이 높다.

핵심 순간 3개를 사용자 상태로 풀면 다음과 같다.

| 순간 | 인지 부하 | 감정 | 손·눈 | 화면에 바라는 것 | 화면이 하면 안 되는 것 |
|---|---|---|---|---|---|
| ① 통화 중(10분) | 매우 높음. 영어로 듣고·생각하고·말하는 것 자체가 작업 기억을 다 쓴다 | 긴장, 수행 불안. 실수했다는 자각이 곧바로 위축으로 이어진다 | 손은 자유롭지 않을 수 있고(폰을 들고 있음), 눈은 화면을 간헐적으로만 본다. 곁눈으로 1초 안에 상태를 읽어야 한다 | 지금 누가 말하는 차례인지, 내 말이 들어갔는지, 시간이 얼마나 남았는지, 끊는 법. 그 외에는 없어도 된다 | 교정·평가·안내문을 띄우는 것. 상태를 색이나 작은 글자로만 말하는 것. 버튼 위치가 바뀌는 것(AUDIT C5). 내비게이션·배너가 공간을 차지하는 것(C9) |
| ② 리포트 읽기(통화 직후) | 중간. 방금 한 대화를 되짚을 여유는 있지만 피곤하다 | 취약함. 피드백을 받는 순간이라 첫 문장이 평가면 방어적이 된다. 동시에 "그래서 뭘 하면 되는지" 를 알고 싶어 한다 | 자유. 데스크톱이면 스크롤·비교가 가능 | 먼저 "어떤 대화였고 무엇이 됐는지" 를 인정해 주고, 그다음 고칠 것을 **원문→교정→이유** 로, 끝에 **다음에 할 일** 을 | 점수부터 들이미는 것(R1). 원문을 지워 버리듯 표시하는 것(R4). 내부 오류를 그대로 보여 주는 것(R9). 끝에서 행동 없이 끊기는 것(R7) |
| ③ 채팅(틈틈이) | 낮음~중간. 다른 일 사이에 짧게 | 가벼움. 부담 없이 영어를 써 보는 시간 | 자유. 키보드 | 빠른 왕복, 힌트는 보이되 방해하지 않게, 언제든 리포트로 정리 | 힌트가 상대 말처럼 보이는 것(T2). 보내는 동안 입력이 잠기는 것(T8). 종료 후 갈 곳이 없는 것(T5) |

두 가지가 모든 화면을 관통한다. 첫째, 사용자는 **평가받으러 온 것이 아니라 연습하러 왔다**. 둘째, 사용자는 **개발자** 라서 밀도 높은 정보와 정확한 숫자를 읽는 데 익숙하고, 과장·장식·귀여움을 신뢰 저하로 받아들이기 쉽다(Final Round 의 과장 톤, Duolingo 의 마스코트를 가져오지 않는 이유 — RESEARCH 3부).

## 2. 톤 결정

후보 3개를 위 상황과 레퍼런스에 비추어 비교했다.

| 후보 | ①통화 중 | ②리포트 | ③채팅 | 레퍼런스 근거 | 판단 |
|---|---|---|---|---|---|
| 차분한 코치 | 말이 적고 상태만 알려 준다 — 맞음 | 인정 → 교정 → 다음 과제 구조와 맞음. "실수를 짚되 사람을 평가하지 않는다" | 조금 건조할 수 있음 | Speak(대화 중 교정을 아끼고 사후에 몰아줌, "짚을 것 3가지"), Cambly(남은 시간을 "마무리 시간" 으로 의미 부여), interviewing.io(척도에 의미 부여, 잘한 점→개선점) | **채택(기본 목소리)** |
| 친근한 대화 상대 | 통화 중 상대는 이미 영어 페르소나(AI)다. UI 까지 친근하게 말을 걸면 두 화자가 생긴다 | 교정을 "친구가 농담처럼" 하면 성인 학습자에게 가볍게 들린다 | 맞음 | Duolingo(격려·마스코트는 아동·게임 문맥), Speak 의 "튜터가 당신을 기억해요" 류 연속성 문구는 유효 | 기각(기본), 단 시작·칭찬 순간의 **온기** 만 가져온다 |
| 개발자 도구 감성 | 정보 밀도·정확한 숫자·조용한 색 — 통화 화면의 "한눈에" 에 맞음 | 숫자만 나열하면 차갑고 판정처럼 읽힌다("오류 3건") | 맞음 | Linear(노이즈 줄이고 위계·밀도 올리기), Vercel Geist(주/보조/3차 텍스트, tabular figures), Grammarly(정확성과 제안을 색으로 분리) | 기각(목소리), 단 **시각 언어** 로 채택 |

**결정: 목소리는 "차분한 코치", 시각 언어는 "개발자 도구 감성", 온기는 시작·칭찬 순간에만.**

- 목소리(무엇을 어떻게 말하는가): 짧고 구체적이며 평가하지 않는다. 실수는 문장 단위로 짚고 이유를 한 줄로 말한다. 사용자를 2인칭으로 부르지 않고(이름·"님" 남발 금지) 행동을 말한다.
- 시각(어떻게 보이는가): 중립 팔레트 + 강조색 1개, 숫자는 tabular, 여백으로 구획, 장식·이모지 없음, 다크 모드 기본 지원.
- 온기(언제 풀어지는가): 통화 시작 전("상대가 먼저 인사해요"), 리포트 첫 문단(대화의 성취를 먼저), 칭찬 코멘트. 그 외에는 담백하게.
- 기각 이유 요약: 순수 "친근한 대화 상대" 는 UI 와 AI 페르소나가 겹치고 성인·시험 문맥과 어긋난다. 순수 "개발자 도구" 는 피드백 순간의 정서(BRIEF ②)를 다루지 못한다.

### Voice & tone 차트

목소리는 하나(차분한 코치), 톤은 상황에 따라 세기가 바뀐다. 문장 예시는 2단계 `WRITING.md` 의 규칙(해요체, 동사형 버튼)으로 쓴 것이며 최종 문구는 `STRINGS.md` 개정표를 따른다.

| 상황 | 사용자 상태 | 톤 | 하는 것 | 하지 않는 것 | 예시 |
|---|---|---|---|---|---|
| 시작할 때(홈, 통화 전, 새 채팅) | 망설임 | 따뜻하고 짧게 | 첫 행동 하나를 분명히. 무엇이 일어날지 한 문장 | 긴 설명, 기능 나열, 환영 인사 반복 | "상대가 먼저 인사해요. 편하게 영어로 답하면 돼요." / 버튼 "통화 시작" |
| 통화 중 | 긴장, 곁눈질 | 극도로 절제 | 상태를 명사 하나로("듣는 중", "상대가 말하는 중"). 시간은 숫자만 | 격려·교정·팁·문장 | "듣는 중" / "1분 남았어요" (status) |
| 실수를 짚을 때(리포트 교정, 힌트) | 취약함 | 중립, 구체적, 짧게 | 원문 → 고친 문장 → 이유 한 줄. 규칙을 말하되 사람을 말하지 않는다 | "틀렸다", "실수", "오류" 같은 판정어. 취소선. 느낌표 | 원문 "I go to school yesterday" → "I went to school yesterday" — 지난 일은 과거형으로 써요 |
| 칭찬할 때(리포트 요약·코멘트) | 피곤, 확인받고 싶음 | 구체적으로 한 번 | 무엇을 해냈는지 사실로("질문 6개에 모두 답했어요") | 과장("완벽해요!"), 별·점수 폭죽, 매번 칭찬 | "10분 동안 면접 질문 6개에 답했어요. 과거 경험을 말할 때 시제만 다듬으면 돼요." |
| 오류가 났을 때 | 당황 | 침착, 해결 중심 | 무슨 일이 / 왜 / 다음에 할 것. 버튼에 행동 이름 | 사과 남발, 기술 용어, 코드, 사용자 탓 | "답변을 받지 못했어요. 네트워크를 확인한 뒤 다시 보내 주세요." / 버튼 "다시 보내기" |
| 비용·한도 안내(턴 상한, 사용량, 연장) | 무심 또는 궁금 | 사실 그대로 | 숫자와 단위, 무엇이 제한되는지 | 경고조, 죄책감 유발 | "이 대화는 60번까지 보낼 수 있어요. 리포트를 만들거나 새 대화를 시작해 주세요." |
| 운영 상태(모의 모드, API 키 없음) | 사용자 대부분은 무관 | 조용히, 운영자에게만 | 한 줄, 상단이 아닌 설정/상태 영역 | 모든 화면 최상단 전폭 배너, `.env` 같은 파일명 | "지금은 연습용 가짜 응답이에요(모의 모드)." |

## 3. 디자인 원칙 5개

각 원칙에 "이 원칙 때문에 하지 않는 것" 을 붙였다. 4단계 화면 결정과 7단계 리뷰의 기준이다.

### P1. 통화 중에는 한 번에 하나만

통화 화면은 1초 안에 읽혀야 한다. 상태 1개(누가 말하는 차례인지), 시간 1개(남은 시간), 행동 1개(끊기)가 가장 크고, 나머지는 작거나 없다. 상태는 색·아이콘·글자 셋으로 동시에 말한다(WCAG 1.4.1, Apple "색에만 의존하지 않기", Google Meet 의 "화자 = 파란 테두리 하나").
- 하지 않는 것: 통화 화면에 전역 헤더·내비게이션·운영 배너를 두지 않는다. 통화 중에 교정·팁·격려를 띄우지 않는다. 버튼의 위치를 통화 도중에 바꾸지 않는다(연장 버튼이 끼어들지 않는다). 13px 알약 하나로 상태를 말하지 않는다.

### P2. 숫자보다 다음 행동

리포트의 모든 정보는 "그래서 다음에 무엇을 하면 되는가" 로 이어진다. 순서는 인정(요약) → 점수(맥락 있는 숫자) → 교정(원문·교정·이유) → 다음 과제(바로 누를 수 있는 행동). 점수에는 해석 문장을 붙인다(interviewing.io 의 "3 이상이면 채용권" 처럼 척도에 의미를).
- 하지 않는 것: 종합 점수 하나로 사람을 판정하지 않는다. 원문에 취소선을 긋지 않는다. 리포트를 번호 목록으로 끝내지 않는다. 내부 오류 문자열을 사용자에게 보여 주지 않는다.

### P3. 같은 뜻은 같은 말, 같은 역할은 같은 모양

용어집(WRITING) 하나, 컴포넌트(SYSTEM) 하나. "전화 영어/통화", "리포트/보고서", "상대/AI" 처럼 같은 개념에 두 단어를 쓰지 않는다. 필터는 필터처럼, 1차 행동은 1차 버튼처럼 보인다.
- 하지 않는 것: 화면마다 다른 날짜 형식·버튼 라벨. 필터에 1차 버튼 스타일(AUDIT K1). 같은 자리의 버튼이 상황에 따라 다른 곳으로 가는 것(D2, R12). 네이티브 `select`·`confirm` 으로 비교·확인을 대신하는 것(S1, P1).

### P4. 접근성은 기본값이지 옵션이 아니다

텍스트 4.5:1, UI 경계·포커스 링 3:1, 터치 타깃 44px(통화 주요 버튼 56px), 키보드만으로 전 흐름, `prefers-reduced-motion` 에서 모션 정지·페이드, 상태 변화는 `role=status/alert` 로. 다크 모드는 반전이 아니라 별도 팔레트(Apple Dark Mode, M3 surface 단계).
- 하지 않는 것: 대비가 모자란 "예쁜" 색을 장식이라며 남기지 않는다. 모션으로만 상태를 전하지 않는다. 포커스 링을 지우지 않는다. 표를 모바일에서 가로 스크롤로 방치하지 않는다. 비활성 버튼을 흐리게만 두고 이유를 숨기지 않는다.

### P5. 조용한 화면, 분명한 글

중립 팔레트에 강조색 1개(1차 행동과 "상대가 말하는 중"), 상태색 3개(positive/caution/negative)만 쓴다. 서체 1종, 텍스트 위계 3단(주/보조/3차), 숫자는 tabular. 글은 짧고 구체적이며 사용자가 할 수 있는 행동으로 끝난다(Linear "노이즈를 줄이고 위계를 올린다", Vercel Geist 의 Label/Copy 분리).
- 하지 않는 것: 이모지를 아이콘으로 쓰지 않는다. 과장("완벽", "최고")·느낌표 남발을 하지 않는다. 운영자용 정보(`.env`, 환경 변수 이름, 모의 모드)를 사용자 화면 상단에 두지 않는다. 한 화면에 1차 버튼을 둘 이상 두지 않는다.

T4·T5·T6·T8·T10·A3·A4·L2·S2·S5·S7·K4 는 2단계 문구 규칙(오류 구조, 빈 상태 구조, 확인 대화)과 5단계 상태 설계가 담당한다.
