# 시안 console — 콘솔

CSS: `src/app/directions/console.css` · 촬영: `shots/`(48장, `index.md`·`axe.md`·`overflow.md`) · 보는 법: `?direction=console`

## 1. 한 줄

서비스를 **내 영어의 세션 로그를 남기는 터미널**로 보이게 한다. 대화는 화자 열이 붙은 로그 행, 힌트는 `//` 주석, 교정은 −/+ diff, 통화는 상태줄과 사각 키.

## 2. 왜 이 서비스에 맞는가 (00-understanding 4절의 다섯 가지)

1. **장소**: 열자마자 `$ LEO` 프롬프트, 1px 경계의 패널, 모노스페이스 영어가 보인다. 개발자에게는 "매일 쓰는 도구"의 자리이고, 다른 영어 앱과 겹치지 않는다.
2. **영어가 주인공**: 영어 문장·숫자·시각만 IBM Plex Mono 15px, 한국어 UI 는 IBM Plex Sans KR 13~15px. 같은 가족이라 어울리면서도 영어 행이 눈에 먼저 들어온다.
3. **통화는 통화답게**: 상단 상태줄(`$ LEO` · 테마 · 모노 시계 40px), `●` 가 깜빡이는 상태 행, 로그 패널, 하단에 사각 키 3개(끊기는 빨강 면). 말풍선·링 타이머가 없어 "타이머 달린 채팅창"으로 읽히지 않는다.
4. **리포트는 코치의 메모답게**: 점수는 `6/10` 과 10칸 분할 막대(측정값으로 읽힘), 교정은 `− 원문` / `+ 교정문` 두 행. "틀렸다"가 아니라 "이 줄을 이렇게 바꿔라"는 코드 리뷰 문법이라 개발자에게 익숙한 피드백 형식이다.
5. **라이트·다크 각각**: 다크가 기본 분위기(#0d1117 캔버스 위 시안 #39c5e0). 라이트는 반전이 아니라 "종이 같은 터미널"(#f6f8fa 위 틸 #0e7490)로 따로 짰다.

## 3. 어떤 사용자 이해에서 나왔는가

긴장을 **정확함과 통제감**으로 다룬다. 시험 앞의 개발자에게 가장 안심되는 것은 위로가 아니라 "무엇이 어떻게 기록되고, 무엇을 고치면 되는지"가 숫자와 행 단위로 보이는 상태다(interviewing.io 가 "detailed, actionable feedback" 으로 신뢰를 세우는 방식). 로그 형식은 실수를 사람의 평가가 아니라 **수정 가능한 줄**로 바꿔 준다. 대신 온기는 문구(WRITING.md)에만 맡기고 시각은 담백하게 둔다.

- **서체**: 한국어 UI `"IBM Plex Sans KR"`(400·500·600·700), 영어 대화·예문·교정문·숫자·시각·배지·표·메타·입력창 `"IBM Plex Mono"`(400·500·600). Hangul 은 Mono 에 없어 폴백으로 Sans KR 이 섞인다(배지 "리포트 있음" 등). 본문 15px/1.6, 영어 15px/1.6, 메타 12~13px, h1 20px 600, 시계 40px 500, 입력창은 iOS 확대 방지로 16px.
- **형태**: 모서리 2~3px(알약 토큰 `--radius-full` 도 3px), 1px 경계, 그림자 없음. 간격 토큰을 한 단계씩 줄였다(space-4 16→12px 등). 카드는 "패널": 제목이 가라앉은 색 띠 + 아래 괘선(탭 바). 목록은 한 패널 안의 행이고 행마다 `01`, `02` 번호가 붙는다.
- **헤더 = 상태줄**: 44px, `$ LEO`, 현재 메뉴는 알약이 아니라 2px 시안 밑줄. 모바일은 왼쪽 2px 막대.
- **대화 = 로그 행**: 말풍선 없음. 각 행은 `4rem(모바일 3rem) + 1fr` 격자로 화자 열("나:" 시안, "상대:" 회색)과 본문 열. 상대 행은 패널색, 내 행은 캔버스색, 행 사이 1px 괘선. 힌트는 같은 격자의 `//` 행(초록 모노). 입력창 앞에 `$` 프롬프트, 인식 중 문장은 이탤릭 + 왼쪽 시안 막대.
- **통화**: 상태줄(브랜드·테마·모노 시계, 링은 숨김) → 상태 행(`●` + 아이콘 + 글자, 듣는 중 초록 1.2s·말하는 중 시안 0.8s 깜빡임, 음소거 빨강 고정) → 로그 패널 → 사각 키(음소거 / 끊기 빨강 면 / 연장). 음소거 눌림은 옅은 빨강 면.
- **리포트**: 목차는 번호가 붙은 탭 줄. 점수는 모노 `6/10` + 10칸 분할 막대(등급색 채움). 교정은 1px 경계 상자 안에 `− 원문`(옅은 빨강 행) / `+ 교정문`(옅은 초록 행, 제안은 옅은 시안 행), 설명은 아래 행. 라벨("내가 한 말"/"이렇게 말해요")은 왼쪽 열에 11px 로 남겼다.

## 6. 이 방향을 택하면 포기하는 것

- **온기.** 리포트 요약("…말했어요")과 교정 행이 코드 리뷰처럼 차갑게 읽힐 수 있다. 문구가 온기를 전부 떠안는다.
- **개발자가 아닌 사용자.** `$`, `//`, −/+ 는 개발자에게만 자명하다. 사용자 2명이 개발자라는 전제(00-understanding 2절)에 기댄 선택이다.
- **여백.** 밀도를 올렸으므로 1280px 에서도 화면이 "꽉 찬" 느낌이고, 숨 쉴 자리가 적다.
- **한글 조판의 균일함.** Mono 와 Sans KR 이 한 줄에 섞이는 자리(배지·메타·힌트의 한국어)가 생긴다.
- **링 타이머.** 남은 시간의 비율 표시를 숫자만으로 대신한다(10절 참고).

## 7. 이전 산출물에서 바꾼 것

- `PRINCIPLES.md` P5 "서체 1종": 2종(Sans KR + Mono)으로 바꿨다. 영어를 주인공으로 만들려면 UI 와 다른 목소리가 필요하다(00-understanding 4절 2번).
- P5 "강조색 1개·상태색 3개": 유지. 다만 강조색이 파랑에서 시안/틸로 바뀌고, "나" 화자 라벨과 `$` 프롬프트에도 강조색을 쓴다(지금 눌러야 할 것 + 지금 말하는 사람 + 나).
- `SYSTEM.md` 1절 `bubble-me`: 채워진 파란 말풍선 → 캔버스색 행. `bubble-partner` 는 패널색 행. 말풍선 토큰을 "행 배경"으로 재해석했다.
- `SYSTEM.md` 3절 라운드 6/10/14/20/999 → 2/3/3/3/3, 그림자 전부 none, 간격 한 단계 축소. 2.2 절 스케일: body 16→15, headline 24→20, english 17→15(모노는 같은 크기에서 더 넓어 보임), display 는 시계 전용 40px/500.
- 말풍선의 숨겨진 화자 라벨(`.sr-only`)을 보이게 되돌렸다(02-build-rules 1절 허용 방식). 장식 글리프(`$`, `//`, `−`, `+`, `●`, 번호)는 CSS `content` 로만 더했고 문구는 바꾸지 않았다.
- "개발자 도구 감성 = 시각 언어" 결정(PRINCIPLES 2절)을 가장 멀리 밀어붙인 시안이다. 현행이 Linear 류의 "정돈된 SaaS"였다면 이 시안은 터미널 그 자체다.

## 10. CSS 만으로 못 한 것 (2차 세션 목록)

1. **타이머 링을 숨겼다.** 남은 시간 비율이 숫자로만 남는다. 터미널답게 `[██████░░░░] 0:20` 같은 텍스트 진행 막대를 두려면 `Timer.tsx` 에 요소가 필요하다.
2. **화자 열의 글자는 `.sr-only` 라벨("나: ")을 되돌린 것이다.** 콜론이 문구에 들어 있어 열 정렬·행 시각(타임스탬프)·행 번호를 붙일 수 없다. `Bubble.tsx` 에 화자 셀과 시각 셀을 두는 편이 맞다.
3. **diff 라벨("내가 한 말"/"이렇게 말해요")이 셀로 남는다.** 진짜 unified diff(행 번호, 단어 단위 강조)는 `DiffText.tsx` 에서 토큰을 나눠야 한다. −/+ 기호는 CSS `content` 라 복사·보조 기술에서는 빠진다(대체 텍스트 `/ ""` 로 읽히지 않게 했다).
4. **통화 상태 행에 아이콘과 `●` 가 함께 있다.** 아이콘 자리를 상태 토큰(글자)으로 바꾸려면 `CallStatus.tsx` 수정.
5. **패널 제목 띠**는 `h2` 의 음수 마진으로 만든 것이라 카드 패딩과 묶여 있다. `Card.tsx` 에 `.panel-head` 요소를 두면 안전하다.
6. **목록·목차의 번호는 CSS 카운터**라 보조 기술·복사에서 빠진다. 번호가 의미라면 마크업으로.
7. **리포트 목차에 현재 절 표시가 없다.** 스크롤 스파이(JS) 필요.
8. **`select` 팝업과 체크박스 네이티브 모양**은 `color-scheme` 만 따른다. 사각 체크박스 그림은 커스텀 컨트롤이 필요하다.
9. **헤더 상태줄에 넣고 싶은 정보(모의 모드, 남은 사용량, 현재 시각)** 는 마크업 없이는 못 넣는다. 지금은 `모의 모드` 배지만 사각으로 바꿨다.
10. **입력창 16px vs 본문 15px** 불일치는 iOS 확대 방지 때문이며 마크업 문제는 아니다. 통일하려면 본문을 16px 로 올려야 한다.
