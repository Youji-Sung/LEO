# 디자인 4종 (사용자 기능)

LEO 는 사용자가 설정에서 고르는 디자인 네 가지를 가진다: **기본 `basic`**, **서재 `study`**, **무대 `stage`**, **콘솔 `console`**. 네 디자인은 모두 정식 기능이며 마크업·문구·흐름·기능은 공통이고, 디자인은 CSS(와 생성된 색 토큰)만 다르다. 선택은 설정 → 화면 → 디자인 시안에 있고 `UserSettings.direction` 에 저장되며, 쿠키 `leo_direction` 으로 서버가 첫 HTML 부터 그 디자인으로 렌더한다.

> 역사: 2026-11-04 1차 세션이 서재·무대·콘솔 세 시안을 비교용으로 만들었고(문서 `00-understanding.md` → `01-exploration.md` → `02-build-rules.md` → 시안별 `README.md` + `shots/`), 운영자가 2026-11-05 에 하나를 고르는 대신 넷을 모두 사용자 기능으로 두기로 했다(`../VISUAL_BRIEF.md` "다음 작업"). 같은 날 2차 세션이 네 디자인을 전 화면에서 같은 완성도로 다듬었다(`../POLISH_PLAN.md`, 결과 `../POLISH_PROGRESS.md`, 결정 `../DECISIONS.md` "시안 4종 다듬기"). 1차 세션의 추천(서재)은 참고 기록이며 기본값은 바뀌지 않았다(`basic`).

## 각 디자인의 상태 (2026-11-05)

- **공통**: 46개 상태 × 1280/390 × 라이트/다크 촬영(`../screenshots/directions/<디자인>/`), 360/640/768 폭(`widths/`), reduced-motion(`reduced-motion/`). 키보드 E2E 3개 흐름이 네 디자인에서 통과. 외부 테스트 피드백 6건 반영(`../POLISH_PROGRESS.md` 1단계).
- **기본**: 1단계 변경(첫 인사 저장, 예문 라벨, 글 입력 전환 안내, 재전송) 외에 모양 변화 없음. 3단계의 새 마크업(화자 라벨, 타이머 막대, 스위치 트랙, 단어 diff)은 숨기거나 모양을 고정했다.
- **서재**: README 10절 7건 중 해결 5, CSS 로 다른 방법 2(통화 상태 아이콘, 홈 카드).
- **무대**: 7건 중 해결 4(막대·화자 라벨·점수 타일·스위치), CSS 로 다른 방법 1(모의 모드 칩), 안 함 2(홈 블록 문구, 상태 알약 위치).
- **콘솔**: 10건 중 해결 5(막대·화자 셀·단어 diff·패널 띠·스크롤 스파이), CSS 로 다른 방법 1(상태 행 아이콘), 안 함 4(시각 셀·번호 마크업, 네이티브 컨트롤, 상태줄 정보, 입력창 16px).
- 공통 과제였던 주소창 `theme-color` 는 네 디자인 모두 현재 canvas 값을 쓴다.

## 로컬에서 보는 방법

1. 서버를 띄운다: `npm run dev` (모의 모드로 보려면 `.env` 에 `CLAUDE_MOCK=1`).
2. **설정 → 화면 → 디자인 시안**에서 기본·서재·무대·콘솔 중 고른다. 고르면 바로 바뀌고 계정에 저장되어 다른 브라우저에서 로그인해도 유지된다. 로그인하지 않은 화면(로그인·회원가입)은 주소에 쿼리를 붙여 볼 수 있다: `?direction=study|stage|console|off`(쿠키 30일). 로그인하면 계정에 저장된 디자인으로 쿠키가 다시 맞춰진다.
3. 다크 모드는 설정의 "테마 모드" 또는 OS 설정. 네 디자인 모두 라이트·다크 팔레트를 따로 가진다(반전이 아님).
4. `.env` 의 `LEO_DIRECTION=study|stage|console` 은 쿠키가 없을 때의 기본값(개발용).
5. 서재·콘솔의 폰트는 Google Fonts 에서 받으므로 인터넷이 필요하다(기본 Pretendard 도 jsDelivr).

스크린샷을 다시 찍으려면 `npx tsx scripts/screenshots.ts --direction <디자인> --axe --port 315x`(디자인마다 다른 포트: basic 3150, study 3151, stage 3152, console 3153). 1차 비교 세트(9개 상태)만 찍으려면 `--compare`.

## 구현

- 색 팔레트의 단일 출처는 `src/design/directions.ts`(기본은 `src/design/tokens.ts`). `npx tsx scripts/build-tokens.ts` 가 `src/app/directions/tokens.css` 를 생성하고, 단위 테스트가 동기화와 대비(네 디자인 × 라이트/다크 × 33쌍)를 고정한다.
- 서체·간격·라운드·컴포넌트 재정의는 `src/app/directions/<디자인>.css` 한 파일씩이며, 모든 규칙이 `[data-direction="<디자인>"]` 아래에 있다(`02-build-rules.md`). 루트 레이아웃이 쿠키로 `<html data-direction>` 과 폰트 `<link>` 를 넣고 `theme-color` 를 그 디자인의 canvas 로 준다.
- 마크업은 공통이다. 디자인이 필요로 한 요소(화자 라벨 `.bubble-speaker`, 타이머 막대 `.timer-bar`, 점수 분자·분모, 카드 `.card-head`, 단어 diff `.diff-word-*`, 힌트 스위치 트랙, 목차 `aria-current`)는 기본 디자인에서 숨기거나 모양을 고정한다.

## 남은 과제

- **CSS 분리 로드**: 네 디자인의 CSS 가 한 번들로 모두 전송된다(기본 사용자도 115KB, 2026-11-04 의 41.6KB 에서 증가). 디자인별 CSS 를 선택된 것만 `<link>` 로 싣는 구조가 필요하다.
- **서재·콘솔의 폰트 전송량**: Google Fonts 한글 unicode-range 분할로 CSS +240~280KB, 폰트 +140~250KB. 셀프호스팅 서브셋을 검토할 것.
- **무대 통화 상태 알약 위치**(시계 옆), **무대 홈 블록 문구**, **콘솔 시각 셀**: 공통 마크업·흐름 변경이 필요해 보류(`../DECISIONS.md` 3단계 "안 한 것").
- 실제 기기 확인: 마이크·TTS·끼어들기, Android Chrome 의 통화 화면, OS "동작 줄이기", 스크린리더 낭독(화자 라벨 "나: " 순서)은 클라우드 세션에서 확인하지 못했다.
