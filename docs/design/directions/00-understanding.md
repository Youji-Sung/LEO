# 서비스와 사용자에 대한 이 세션의 이해 (1단계)

2026-11-04. 모의 모드(`CLAUDE_MOCK=1`)로 서비스를 띄워 13개 화면(로그인, 홈, 채팅 목록, 채팅, 통화 설정, 통화 시작 전, 통화 중, 기록, 대화 내용, 리포트, 포트폴리오, 사용량, 설정)을 1280px 에서 직접 보고, `screenshots/after/` 의 390px·다크 화면과 `PRINCIPLES.md`·`SYSTEM.md`·`WRITING.md`·`SCREENS.md` 를 읽었다. 아래는 이전 세션의 분석을 그대로 받지 않고 다시 적은 것이다.

## 1. 이 서비스는 무엇인가

- **두 사람이 쓰는 개인 연습실**이다. 가입 유도도, 요금제도, 온보딩 퍼널도 없다. 운영자가 키를 넣고 두 사용자가 들어와 연습한다. 따라서 시각은 "팔기 위한 인상"이 아니라 **"들어가서 연습하고 싶은 장소"** 를 만들어야 한다.
- 제품의 중심 내용은 **영어 대화 텍스트**다. 상대의 말, 내 말, 교정문, 예문, 예상 질문. 한국어는 안내와 조작(UI)뿐이다. 즉 화면에서 가장 많이 읽히는 글은 영어이고, 그 영어가 어떻게 보이느냐가 서비스의 인상 대부분을 정한다.
- 세 순간이 있고 요구가 서로 다르다.
  1. **통화**(10분, 긴장·곁눈질): 지금 누가 말하는지, 남은 시간, 끊는 법. 화면은 "통화 중인 전화기"처럼 느껴져야지 "타이머 달린 채팅창"이면 안 된다.
  2. **리포트**(통화 직후, 취약함): 인정 → 점수 → 교정 → 다음 행동. 코치가 적어 준 메모처럼 읽혀야지 관리자 대시보드처럼 보이면 평가로 느껴진다.
  3. **채팅**(틈틈이, 가벼움): 빠른 왕복과 힌트.
- 통화 설정·기록·포트폴리오·사용량·설정은 보조 화면이다. 통화·리포트·채팅이 정해지면 따라간다.

## 2. 사용자는 누구인가

- 해외 취업을 준비하는 **한국인 개발자**. 성인, 실용적, 정보 밀도에 익숙하고, 귀여움·과장·마스코트를 신뢰 저하로 받아들인다(이전 세션과 같은 판단).
- 그러나 동시에 **시험을 앞둔 사람**이다. 영어로 말하는 것 자체가 부담이고, 실수를 눈앞에서 지적받는 순간이 매번 온다. 연습실은 "안전한 다른 곳"이어야 한다. 이 점을 시각이 어떻게 다루느냐가 방향을 가른다 — 차분함으로(서재), 기세로(무대), 정확함으로(콘솔).
- 데스크톱 Chrome 위주, 통화는 모바일 가능성. 다크 모드 사용자일 확률이 높다(개발자).

## 3. 지금 화면이 왜 "서비스에 맞지 않아" 보이는가 (가설)

운영자가 이유를 적지 않았으므로 세션의 가설이다.

- **익명의 SaaS 관리 화면**이다. 따뜻한 회색 캔버스 + 흰 카드 + 파란 버튼 + 알약 배지. Linear·Vercel 류의 문법을 빌려 와 정돈됐지만, 어떤 제품이어도 같은 모습이다. "영어", "말하기", "연습", "전화" 중 어느 것도 화면에서 읽히지 않는다.
- **영어와 한국어가 같은 옷**을 입고 있다. Pretendard 한 종으로 UI 와 대화가 같은 크기·같은 결이라 대화가 UI 속에 묻힌다.
- **통화 화면이 채팅처럼 보인다.** 말풍선 목록 위에 작은 상태 카드와 링 타이머. 전화기의 긴박함·간결함이 없다.
- **리포트가 표처럼 보인다.** 카드 7개가 같은 모양으로 쌓이고, 점수 바가 대시보드 위젯처럼 읽힌다.
- **브랜드가 없다.** `LEO` 는 텍스트 한 단어이고 색·형태·서체 어디에도 고유성이 없다.

## 4. 시각 방향이 반드시 해야 하는 일

1. **장소를 만든다.** 열면 "여기는 영어 말하기 연습실"이라고 1초 안에 느끼게.
2. **영어 대화를 주인공으로.** 영어 텍스트에 UI 와 다른 목소리(서체·크기·여백)를 준다.
3. **통화는 통화답게.** 상태·시간·끊기가 큰 덩어리로 보이고 나머지는 물러난다.
4. **리포트는 코치의 메모답게.** 판정이 아니라 다음에 할 일로 읽히게.
5. **라이트·다크 모두 설계.** 반전이 아니라 각각의 분위기.

## 5. 이전 산출물 중 가져가는 것과 열어 두는 것

- 가져간다: 문구 규칙(`WRITING.md`)과 문구 전체, 접근성 하한(텍스트 4.5:1, UI 3:1, 타깃 44/56px, reduced-motion), 통화 컨트롤 격자(`1fr auto 1fr`)와 화면 구조(섹션 순서, 목차, 두 줄 교정). 이것들은 시각 방향과 독립이며 바꿀 이유가 없다.
- 열어 둔다: 팔레트, 서체 조합, 라운드·그림자·경계, 밀도, 표면 구성(카드 중심인지 아닌지), 브랜드 표기, 통화 화면의 구성, 리포트의 섹션 표현. `PRINCIPLES.md` P5("조용한 화면")와 "개발자 도구 감성 = 시각 언어" 결정은 **이번에 다시 묻는다.**

## 6. 비교 기준이 될 화면 세트 (세 시안 공통)

운영자가 서비스를 판단하는 데 필요한 화면만 고른다. 보조 화면은 하나(설정)만 넣어 폼·선택 컨트롤의 모양을 비교한다.

| 화면 | 왜 필요한가 |
|---|---|
| 로그인 | 첫인상, 브랜드 표기 |
| 홈 | 장소의 분위기, 1차 행동, 목록 |
| 통화 설정 | 선택 카드·라디오·안내 메시지 |
| 통화 시작 전 | 전용 레이아웃의 첫 화면 |
| 통화 중 · 음소거 · 종료 중 | 핵심 순간 ①. 상태·시간·끊기 |
| 채팅(힌트 포함) | 핵심 순간 ③. 말풍선·힌트·입력 |
| 리포트(채팅·면접 / 통화·면접) | 핵심 순간 ②. 점수·교정·다음 행동 |
| 기록 | 목록 밀도, 배지, 필터 |
| 설정 | 라디오 카드·select·저장 |

각 화면을 1280px·390px × 라이트·다크로 찍는다(`scripts/screenshots.ts --direction <이름>`).
